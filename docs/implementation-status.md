# Implementation status

The local prototype is playable from start through victory or defeat. Its implementation follows the supplied dossier with the explicit original/provisional rules in [rules-decisions.md](rules-decisions.md). No empirical live-game validation has been performed; exact behavioral fidelity is not claimed.

Status meanings: **Implemented/tested** = exercised through ordinary play or an executable fixture with actual resolution. **Provisional** = working, tested behavior whose live ordering/semantics remain uncertain. **Fixture support** = executable infrastructure intentionally absent from the neutral playable pool. **Deferred** = no claimed behavior.

## Known gaps and highest-value next step

There are no intended implementation blockers to the local start-to-terminal playable path. The remaining fidelity blockers are empirical: event order, cast/use granularity, cleanse, Lifesteal, repair/Transform inheritance, storm and the other recorded live questions. The 40–60 minute target needs human playtesting; no test asserts a session duration. Hero-specific acquisition rules, optional reserved shop offers, production services, custom crafting/resource networks and alternate renderer ports remain deferred or excluded.

The highest-value product step is a human run with the revised controls, noting readability, drag accuracy and inspection friction, followed by timed runs to tune economy and opponent difficulty. For mechanical fidelity, validate simultaneous timers, empty-ready Reload, crit/multicast counting and Regen/Poison/Burn ordering against controlled live observations. Keep the established JSON fixtures as the regression boundary.
